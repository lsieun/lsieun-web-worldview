# 多人时间轴模板

适用于 `src/_includes/person-timeline-page.html`，以及配套的 `person-filter.html`、`person-lifeline.html`、`person-age-table.html`。当前页面：`/figures/chu-han.html`（楚汉人物）、`/figures/qing.html`（清朝人物）、`/figures/three-kingdoms-ages.html`（三国人物）。

用途：把同一时代的多位人物放在统一时间尺度上，比较“大事发生时，各自几岁、在不在场”。

## 一、页面结构

四段，编号即成阅读顺序：

1. **页头**：水印、标题、副标题、标签、统计（人物数、大事数、年龄口径=虚岁）。
2. **00 · CAST**：人物选择器。
3. **01 · LIFELINES**：生命线图。
4. **02 · AGE MATRIX**：年龄明细表。

页面本身只做三件事：注入数据、include 三个片段、套上页头。文案来自 `timeline.meta`，不写死在片段里。

## 二、数据契约

模板接受两种来源，字段基本一致：

| 来源 | 页面写法 | 说明 |
| --- | --- | --- |
| 实体库视图 | `{% set timeline = world.timelines["chu-han"] %}` | `views/*.json` 经 `world.js` 拼装，自动带 `birthLabel/deathLabel` |
| 独立数据文件 | `{% set timeline = qingTimeline %}` | `_data/qingTimeline.json` 直接提供完整结构，拉丁年份按数字回退显示 |

结构：

```text
{
  start, end,
  meta: { key, watermark, title, subtitle, tags, intro,
          lifelineHint, tableIntro, note },
  groups: [{ id, name, desc }],
  people: [{ id, name, birth, death, birthLabel, deathLabel, group, role }],
  events: [{ year, title, desc, axis, key, era, focus: [id] }],
  personalEvents: [{ year, person: id, title, desc }],
  defaultPeople: [id]
}
```

要点：

- `meta.key` 同时作为过滤器在 `localStorage` 里的页面键；缺省时退回空键。
- `axis: true` 的事件才上左侧年份轴；其余事件仍进年龄表。
- `focus` 点名的事件在对应人物线上显示为实心节点。
- `personalEvents` 是个人里程碑，不要求是时代大事，但在图上与事件节点同样对待。
- `start` / `end` 是展示窗口，不要求覆盖所有人物生卒；超出窗口的生命线会被截断。

## 三、生命线图

### 3.1 坐标

- 纵向是时间，自上而下；固定每 18px 一年，每 10 年一条网格线。
- 左侧竖轴约 200px，只画 `axis` 事件：圆点 + 年份 + 标题。
- 事件标签过密时向下轻推（保持至少 2px 间距），不隐藏；这是纯布局避让，不改变年份位置。
- 每个人物一列，列宽取 `max(84, (可用宽 - 200) / 人数)`；人数多时横向滚动，不压缩到不可读。宽屏（≥1180px）默认随页面越界排版；若图表总宽仍超出版心，`person-lifeline.js` 给卡片加 `is-overflow`，`.qtg-scroll` 退回容器内横滚，列头吸顶随之取消（滚动容器会打断 sticky，与窄屏惯例一致）。

### 3.2 生命线与节点

- 生命线是生卒区间；超出窗口的部分被裁掉，并加截断标记（顶部 / 底部）。
- 在世期间每遇 `axis` 事件落一个节点，节点数字为**虚岁**（`事件年 - 出生年 + 1`）。
- 若同一年既有时事又有个人事件，以个人事件为准，避免一年叠两个圆点。
- 实心节点 = 与本人直接相关（`focus` 点名或个人事件）；空心节点 = 只是在世经历。
- 悬停 / 聚焦显示提示：`年份 事件`、`人名 · 年龄（虚岁）`、说明文字。
- 列头吸顶，并避让站点自身的 sticky 页头高度。

### 3.3 交互与状态

- 过滤变化时整图重算：可见人物、列宽、列头、生命线、节点全部重建。
- 没有可见人物时显示“请在上方选择至少一位人物”，保留一个矮空态，不留下空白大块。
- 窗口缩放后重渲染，避免列宽与吸顶位置错位。

## 四、年龄明细表

- 行 = `timeline.events` 的每一件大事（包括不上轴的事件）；列 = 每个人物。
- 单元格三种状态：
  - 事件年早于出生：`未生`；
  - 晚于去世：`已故`；
  - 在世：虚岁数字 + `岁`。
- 列头显示姓名与生卒，点击可单独聚焦该列，再点一次取消。
- 表格窄屏横向滚动，最小宽度 960px；列头吸顶。
- 过滤只切换列的 `display`，不重排 DOM，保证主键与列顺序稳定。

**已定**：同一批事件同时出现在图和表里；图负责“看见位置”，表负责“读出年龄数字”。不把个人事件加进表，否则表会从“时代大事对照”退化成流水账。

## 五、人物过滤器

- 按 `groups` 分组，组头复选框支持三态（全选 / 部分 / 未选）。
- 每个人物一个复选框；另有 `全选` / `清空` / `默认` 三个快捷按钮。
- 状态存 `localStorage["worldview-person-filter"][pageKey]`，按页面隔离。
- 初始值优先级：已存状态 > `defaultPeople` > 全部人物。
- 变更时派发全局事件 `personfilter:change`，生命线图与年龄表各自订阅后重渲染。
- 初始化延后到 `DOMContentLoaded`，确保后续视图脚本已注册监听。

**已定**：默认只展示一组“有代表性”的人物，而不是全量。全量人物会让首屏列数过多、比较失焦；需要全量时点“全选”。

## 六、已定决策与理由

1. **纵向时间 + 横向人物列。** 同一年的年龄横向并排，最容易比较；若横向是时间、纵向是人，视线要上下找同一年。
2. **只用虚岁。** 与史书“时年若干”的习惯一致，页头与表下注释都明确写出，避免与现代周岁混用。
3. **图与表双视图。** 图看“在不在场、早不早”，表看“具体几岁”；两者共享过滤器，避免各自维护一套选择状态。
4. **只把大事上轴。** 轴上的事件太多会让标签挤在一起；非轴事件仍保留在表里，信息不丢。
5. **个人事件压过同年大事。** 同一年一根线上只保留一个节点，个人事件更贴近“这个人的转折”，优先显示。
6. **人数多时横向滚动。** 最小列宽 84px 保证年龄数字与节点可读；压缩列宽会让人名和年龄同时变得难认。宽屏图表宽于版心时以 `is-overflow` 切换为容器内横滚，宁可放弃列头吸顶也不裁掉人物列。
7. **过滤状态按页面存。** 楚汉与清朝的人物集合不同，共用一个键会互相污染。

## 七、边界与待定

- **依赖 JavaScript（已接受的边界）**：生命线图完全由 `person-lifeline.js` 生成；无脚本时只剩年龄明细表（表是构建期 HTML）。若未来要求无脚本也能看图，需要在构建期输出静态 SVG。
- **无轴事件则不画图（边界）**：`person-lifeline.js` 在 `axisEvents` 为空时直接返回。新增专题至少要有 1 件 `axis: true` 的大事。
- **纵向比例固定 18px/年（待定）**：没有缩放控件。跨度很长（如数百年）时页面会很高；是否需要像帝系与群臣那样提供比例滑条，尚未决定。
- **年份刻度是裸数字（待定）**：图上 10 年网格直接显示 `String(year)`。公元前后的专题需要显式「前 / 公元」，否则公元 1 年前后容易误读。
- **个人事件不进表（边界）**：表只对照时代大事；个人里程碑只在图上出现。
- **`events` 与 `personalEvents` 可能重复**：同一事件若同时登记在两处，图上会以个人事件为准，但表里仍会出现一次。新增数据时应避免重复登记。
- **模板文案中的“七人对比”等标签来自数据**：换专题时改 `meta.tags`，不要改模板。
