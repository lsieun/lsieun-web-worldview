# 浮动目录 (TOC)

适用于 `src/_layouts/entry.html` 详情页（史册 / 舆图 / 人物）。JS 在运行时从 `.prose` 扫描 `<h2>` / `<h3>` 自动生成嵌套导航，不依赖任何构建插件。

## 一、启用条件

满足以下全部条件才会注入 TOC：

1. 当前页面使用 `entry.html` 布局（有 `.entry-body` 容器和 `.prose` 正文）。
2. `.prose` 内至少有 **2 个** `<h2>` 或 `<h3>` 标题。
3. 视口宽度 ≥ **1360px**。

任一条件不满足时，TOC 不渲染也不占位，页面回退到原有的双栏布局（正文 + 档案侧栏）。

## 二、布局位置

```
 ┌──────────┬──────────────────────────────────┬──────────┐
 │  浮动     │              正文               │  档案     │
 │  目录     │      .prose（max-width 46rem）  │  侧栏     │
 │  140px    │                                │  210px    │
 │  sticky   │                                │  sticky   │
 └──────────┴──────────────────────────────────┴──────────┘
```

- 三列由 `.entry-body` 的 `grid-template-columns: 140px minmax(0,1fr) 210px` 驱动，仅在 `.toc-slot.is-ready` 存在时启用（避免页面内容在 JS 执行前抖动）。
- TOC sticky 对齐页头下方 `top: 105px`，与档案侧栏同高。
- 视口 < 1360px：三列自动回落为两列，TOC 整列隐藏，用户无感知。

## 三、交互细节

### 3.1 自动生成

- 遍历 `.prose` 内所有 `h2, h3`，构建嵌套列表（h2 为父项，h3 为子项）。
- 自动补全 `id`：取标题文字做轻量 slug（保留中文、字母、数字），重复时追加 `-N`。
- h3 必须紧跟在某个 h2 之后才会被归入其子列表；孤立的 h3 会被挂在最后一个 h2 下面。

### 3.2 整体收缩 / 展开

- TOC 顶部有 `‹ 目录` 按钮，点击可将整个 TOC 收成一个竖排文字条（`writing-mode: vertical-rl`），只露出"目录"二字。
- 收缩状态持久化到 `localStorage.wv-toc-collapsed`（`0` = 展开，`1` = 收缩）。
- 用户首次访问默认为展开态。

### 3.3 单节折叠 / 展开

- 每个 h2 条目左侧有 `▸` 折叠按钮，点击可隐藏该 h2 下的 h3 子项。
- 折叠状态按 h2 粒度持久化：`localStorage.wv-toc-fold-<section-id>`。
- h3 条目自身没有独立折叠按钮，随所属 h2 统一折叠。

### 3.4 滚动联动高亮

- scroll 监听（`requestAnimationFrame` 节流）实时追踪当前可见的最新标题。
- 距视口顶部 ≤ 120px 的 h2/h3 判定为"当前可见"，对应 TOC 条目加 `.is-active`（金色加粗）。
- 当前可见章节所在的 h2 组若已折叠，自动展开（并同步持久化状态），让用户看到自己在哪一节。
- 滚到页面底部时，高亮最后一个标题。

### 3.5 平滑跳转

- 点击 TOC 条目触发 `scrollTo({ top, behavior: 'smooth' })`，顶部留 90px 偏移（避开 sticky 页头）。
- 收缩态下点击竖排"目录"只能展开；展开态下点击标题才触发跳转。

### 3.6 回到底部

- TOC 底部有 `↓ 回到底部` 按钮，点击平滑滚到 `.entry-foot`（继续浏览导航区）。
- 按钮只在正文足够长（有滚动空间）且 TOC 处于展开态时显示。

## 四、标题层级约定（给作者的写作规范）

TOC 只识别 `<h2>` 和 `<h3>`，正文标题层级应严格遵循：

| 标签 | 语义 | 用途 |
| --- | --- | --- |
| `<h1>` | 页面标题 | 由 entry.html 页头自动输出，正文里**禁止**再用 h1 |
| `<h2>` | 一级章节 | 文章的主要分节。推荐写法：**"一、xxx"、"二、xxx"、"三、xxx"** 中文数字编号开头 |
| `<h3>` | 二级子节 | 某一 h2 下的细分。可选，用在一节内有明确并列主题时 |

**已定**：

- 详情页的 h2 必须用中文数字编号开头（`一、` `二、` …）。目前人物页、史册专题页已统一，舆图页部分页面未编号（如 `huhunyong.html`、`qinhuai.html`），后续补写时统一改为编号风格。
- h3 不强制编号，直接写主题短语即可（如 `第一 / 第二阶梯界`）。
- 不要出现孤立的 h3（前面没有 h2），否则 TOC 会挂到上一个 h2 下，语义混乱。
- 同一页面内不要跳级（h1 → h3 没有 h2 隔开）。

## 五、不做什么

- 不支持 h4 及更深层级。世界观详情页的结构在 h3 层级已经足够表达，再深反而让正文臃肿。
- 不做全文搜索。搜索是索引页 / 站点级功能，不在 TOC 里重复。
- 不做多页面联动目录（如同一专题下多篇文章的跨页导航）。当前专题页是独立文档，如需跨页导航放在索引页处理。

## 六、技术要点

| 项目 | 值 |
| --- | --- |
| 入口文件 | `src/assets/js/toc.js` |
| 注入点 | `entry.html` 中 `.entry-body .toc-slot` |
| 启动时机 | `DOMContentLoaded`（`defer` 脚本） |
| 样式 | `components.css` 末尾 `.toc-*` 系列 |
| 依赖 | 无外部依赖，纯原生 JS |
| 滚动监听 | `requestAnimationFrame` 节流，`passive: true` |
| SSR 兼容 | 不涉及，纯客户端增强；禁 JS 时 `toc-slot` 不渲染，不影响阅读 |
| 暗色主题 | 全部 CSS 变量驱动，跟随 `[data-theme="dark"]` 切换 |
| 减少动画偏好 | 对 `prefers-reduced-motion` 禁用旋转过渡 |

## 七、已定决策与理由

1. **左侧 TOC 而非右侧 Tab。** 右侧 210px 已用于档案信息（类目、年代、编号），TOC 若塞进侧栏会挤压档案可读性。左侧 140px 独立窄条不与任何既有元素冲突。
2. **1360px 是启用阈值。** 世界观详情页的正文已限宽 46rem（约 736px），加上档案侧栏 210px 和正常间隙，1360px 以下再塞 TOC 会让正文变窄到影响阅读体验。
3. **中文数字编号 h2。** 与项目其他模块（时间轴组名、朝代段位）的编号风格一致，TOC 里一眼能看出文章有几节，顺序不会乱。
4. **首次访问默认展开。** TOC 是导航工具，默认展开让新读者"先看到全貌"，比让用户点一次展开更友好。
5. **不做 h4。** 详情页定位是"单主题 3–5 节，每节 2–4 段"的中长文，h4 意味着一节里还要再拆三层，说明该页主题选得过细，应该拆成多篇。
