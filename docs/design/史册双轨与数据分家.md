# 史册双轨与数据分家

> 日期：2026-11-14

## 背景

原项目只有一套史册（`/history/`），内容全部是中国历史。计划扩展为"中国史册 + 世界史册"双轨导航，同时引入同期中外对比视图。

## 已定决策

### 导航：平级双菜单

顶栏导航从 **史册 / 舆图 / 人物** 变为 **中国史册 / 世界史册 / 舆图 / 人物**。
- 中国史册：沿用 `/history/index.html`，改标题为"中国史册"
- 世界史册：新建 `/world-history/index.html`（路径待定，可调整）

### 数据组织：按目录隔离，不按文件名前缀

中国和世界的实体数据各自放在独立子目录下，**文件名保持现有 slug 格式不变**，避免破坏 id 与引用网络。

```
_data/
  china/                       ← 中国数据（从现有根目录移入）
    dynasties/                 ← 原 _data/dynasties/（24 个文件）
    figures/                   ← 原 _data/figures/（~200 个文件）
    events/                    ← 原 _data/events/（~175 个文件）
    views/                     ← 原 _data/views/（23 个文件）
    regions/
    places/

  world/                       ← 世界数据（新建空骨架）
    eras/                      ← 世界"朝代"= 时期（renaissance, age-of-discovery 等）
    figures/                   ← 世界人物
    events/                    ← 世界事件
    views/                     ← 世界视图
    regions/
    places/
```

**为什么不用文件名前缀？** 因为文件名 == 实体 id，改文件名会破坏所有跨文件引用（`dynasty: "tang"` → `"150-tang"`，`figure: "liyuan"` → `"150-liyuan"`），影响面超过 400 个文件。

### 朝代编号：只改 JSON order 字段，不改文件名

24 个 dynasty JSON 的 `order` 值改成紧凑连续编号 1-24（原先是 10 递增：xia=10, shang=20, ... qing=200）。
- 夏=1, 商=2, 西周=3, 春秋=4, 战国=5, 秦=6, 秦楚之际=7, 西汉=8, 新=9, 东汉=10, 三国=11, 西晋=12, 东晋=13, 南北朝=14, 隋=15, 唐=16, 五代=17, 宋=18, 元=19, 明=20, 清=21
- **注意**：原三国是 order=100 作为父级，下辖 cao-wei=105 / shu-han=106 / eastern-wu=107 / western-jin=110。紧凑编号时需要保留这种父子层级关系（parent 字段已经实现）。具体编号在执行时按 start 年份排序重新分配。

### 视图文件按类型分目录（可选后续优化）

现有 views/ 下 23 个文件没有子分类。未来可以：
```
views/
  chronicle/     ← reign-crowd / timeline 类
  family/        ← family-tree 类
  dynasty/       ← dynasty-reigns 类
```
但这不是当前必须做的，记录在此供后续参考。
