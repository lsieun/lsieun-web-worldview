# 帝系双视图模板

适用于 `src/_includes/dynasty-reigns-page.html`，以及配套的 `reign-timeline.html`、`kinship-tree.html`、`dynasty-reigns.js`、`dynasty-reigns.css`。当前页面：`/history/western-han-emperors.html`、`/history/eastern-han-emperors.html`、`/history/eastern-wu-emperors.html`、`/history/tang-emperors.html`。

用途：同一位皇帝，在"纪年"里是一段统治，在"世系"里是一个血缘节点。把两种顺序并置，既看在位更替，也看出身、入继与废立。

## 一、页面结构

1. **页头**：水印、标题、副标题（有信息含量，写清朝代基本事实——在位年数、皇帝数、关键人物）。
2. **标签与统计**：分两组视觉呈现：
   - `.pm-tags`：chip 样式，朝代标识如"唐朝""24 帝""世系与纪年"
   - `.pm-stats`：数据统计，"正式皇帝 N 位""世系节点 N 个"，**不含"任内大事"**（统计对象模糊）
3. **平铺双视图**：先血缘世系树，后在位纪年，**两个 panel 同时显示**，不再通过 JavaScript 切换显隐。
4. **方法说明**：`meta.note`，写清帝序口径、年份精度、称制/辅政如何处理。

**已定**：两个面板都在构建期完整输出，平铺在文档流中；JavaScript 只负责 ECharts 增强、双向定位与 hash 恢复，不再负责 panel 显隐切换。

**已定**：`reign-switch` 按钮（在位纪年/血缘世系切换）已从模板和 JS 中移除。双向定位通过 panel 内的 `data-reign-link` 链接实现（点击"查看纪年 ↓"或"世系位置 ↗"直接滚动到对方面板对应节点）。

## 二、数据契约

由 `world.reignViews[viewId]` 提供：

```json
{
  "id": "western-han-emperors",
  "title": "西汉历代皇帝",
  "meta": { "watermark", "subtitle", "tags", "intro", "note" },
  "dynasty": { "id", "name", "start", "end" },
  "formalCount": 14,
  "treeCount": 19,
  "rulers": [
    {
      "id", "name", "title", "status", "order", "note",
      "terms": [
        {
          "start", "end", "startLabel", "endLabel", "durationLabel",
          "events": [{ "id", "year", "yearLabel", "era", "title", "desc" }],
          "regencies": [{ "name", "label", "startLabel", "endLabel", "note" }]
        }
      ],
      "treeIncluded": true
    }
  ],
  "regencies": [],
  "treeRoots": [ ... ]
}
```

数据来自三处：

| 数据 | 位置 | 作用 |
| --- | --- | --- |
| 视图配置 | `_data/views/*.json`（`type: "dynasty-reigns"`） | 指定朝代、标题、说明、树内人物 |
| 帝系年表 | `_data/dynasties/*.json` | `rulers`（帝序、在位、事件）、`regencies`（临朝/辅政） |
| 人物事实 | `_data/figures/*.json` | 姓名、生卒、`parents`（世系父节点） |

`world.js` 在构建期完成校验与拼装：帝序唯一、正式皇帝必须有 `order`、过渡人物不得有 `order`、事件必须落在对应在位年段且不能重复分配、世系只有一个树内父节点、世系关系不能成环。

`treeRoots` 节点额外包含（用于 HTML data-* 属性 → ECharts tooltip 丰富内容）：

- `note`：来自 `ruler.note`，包含地位得来方式、大事件等关键描述
- `summary`：来自人物实体 `figure.summary`，死后评价/历史定位
- `tooltipEvents`：`ruler.terms[].events` 展平后的字符串数组（最多 6 条，格式 `"年份 事件标题"`）
- `href`：`#timeline-<id>` 锚点，供 tooltip 底部"查看纪年详情 ↓"链接跳转

**已定**：`eventCount` 字段已从 `reignViews` 中移除（统计对象模糊，"任内大事"与"帝国大事"界限不清）。`treeCount` 保留用于统计世系节点数。

## 三、在位纪年视图

- 纵向是时间，按首位在位起始年排序。
- 每位正式皇帝标数字帝序；过渡人物用 `◇`，不占序号。
- 标题写作"全名 + 个人名"（如「汉文帝 刘恒」）；若个人名已含在称号里则不重复追加。
- 一个皇帝可有多段 `terms`（复位、改元等）；每段显示起止、在位年数，以及与该段重叠的临朝/辅政背景。
- 每段下面列出任内大事：年份、年号（可选）、标题、说明。
- 树内人物才显示"世系位置 ↗"链接，点击跳到对应树节点。
- 极短在位不伪造长度；`durationLabel` 可写"27 日"这类文字，年数默认按无公元 0 年计算。

**已定**：数字只标记正式即位者；临朝、辅政、废立者另列为"同期权力背景"，不与帝序混排。

## 四、血缘世系视图

- 递归输出树：根节点在上，子节点在下，连线只表示父母与子女。
- 节点分三类：
  - 正式皇帝：带帝序；
  - 过渡人物：标"过渡"，不占帝序；
  - 宗亲：标"宗"，写"未即位 · 世系连接"，注明"不计入皇帝序号"。
- 每个节点显示一条在位年段；只有正式/过渡人物（有 `terms`）才有"查看纪年 ↓"链接，点击滚动到纪年视图对应段落。
- 宽树横向滚动；图例说明数字、宗亲与连线含义。

**已定**：世系树只画父系血缘，不画母族、婚姻、过继等关系。当前数据结构也只支持一个树内父节点，多父会直接构建报错，这是有意的限制。

## 五、ECharts 世系图增强

ECharts 在页面加载时即初始化（`ensureChart()` 不再依赖切换动作触发）：

- **数据来源是 HTML 树本身**：脚本从 `.kh-roots > .kh-branch` 读出节点、父子关系、帝序与在位文案，不维护第二份世系数据。
- **HTML 节点通过 data-* 属性传丰富数据**：`data-note`（地位得来+描述）、`data-summary`（评价）、`data-events`（关键事件列表，`||` 分隔）、`data-node-href`（纪年锚点链接）
- **成功后才隐藏 HTML 树**：图表初始化失败时保留 HTML 树，页面仍然完整。

### ECharts 世系树规格

- **布局**：`orient: 'TB'`（从上到下），每个皇帝节点占一行
- **节点样式**：单行扁框 `symbolSize: [156, 38]`（皇帝）/ `[132, 32]`（宗亲），`nodeGap: 36`、`levelGap: 64`
- **label**：单行 `{order}{title}{name}` — 帝序圆 + 谥号 + 真名，rich text 对齐到 20px 行高
- **交互**：
  - 拖动平移、滚轮缩放；
  - 工具栏：缩小 / 放大 / 复位 / 全屏 / 导出 PNG；
  - 悬停显示**丰富 tooltip**（见下）；
  - 聚焦某人时高亮其血缘路径。
- **初始缩放**：`calculateInitialZoom()` 返回适中阅读比例（1.15–1.4），不强制 fit 一屏
- **标签隐藏阈值**：缩到 0.7× 以下自动隐藏 label，放大回 0.75× 以上恢复

### ECharts tooltip 规格

hover 皇帝节点时显示**丰富信息卡**：

```
┌─────────────────────────────┐
│ 第 3 位皇帝                 │  ← 小字金色帝序
│ 唐高宗                      │  ← 大号谥号（serif 字体）
│ 李治                        │  ← 小字真名（muted）
│ 649 — 683                   │  ← 等宽字体在位年段
│                             │
│ 太宗第九子，贞观十七年立为… │  ← note：地位得来+关键描述（截断110字）
│                             │
│ 任内关键事件                │
│ · 650 永徽元年              │
│ · 655 废王立武              │  ← events：关键事件列表（最多6条）
│ · 668 灭百济                │
│                             │
│ 在位期间唐朝疆域达到极盛…   │  ← summary：死后评价（截断70字，斜体，分隔线）
│                             │
│ 查看纪年详情 ↓              │  ← 底部可点击链接，跳 #timeline-<id>
└─────────────────────────────┘
```

**宗亲节点 tooltip**（简洁版）：只显示谥号、身份说明、跳转链接。

**tooltip 防模糊措施**：
- `appendToBody: true`（避免被父容器 transform 影响）
- `textStyle.fontSize: 13px`，tooltip 内联 style 统一 `font-size: 13px`、`line-height: 1.6`
- CSS 规则 `.echarts-tooltip` 强制 `-webkit-font-smoothing: antialiased` + `text-rendering: optimizeLegibility` + `transform: translateZ(0)` 消除 subpixel rendering 偏移
- `maxWidth: 300px`、`padding: [12, 14]`、背景色 `surfaceRaised` + 1px 边框

### 全屏与导出 PNG

- **全屏**：优先用浏览器原生全屏；不可用时退化为页面级全屏（`body` 加 `kh-fullscreen-fallback`），Esc 退出。
- **导出 PNG**：按树的叶子数与层数计算画布（至少 1800 × 1300），离屏实例以 2 倍像素比导出完整图，导出后立即销毁，避免残留在页面。
- **主题**：图表颜色从 CSS 变量读取；监听 `data-theme` 属性变化后重建配置，保留当前缩放与中心点。

## 六、双视图联动

支持以下入口，行为一致：

| 入口 | 结果 |
| --- | --- |
| 点击"查看纪年 ↓" | 滚动到纪年视图对应皇帝年段，聚焦并高亮 |
| 点击"世系位置 ↗" | 滚动到世系视图对应节点，聚焦并高亮（ECharts 可用时同时定位图表） |
| 直接访问带 hash 的链接 | 按 hash 恢复位置（两个 panel 都在，直接定位目标） |

Hash 约定：

- `#reign-timeline` / `#reign-kinship`：定位到对应 panel 顶部
- `#timeline-<人物 id>`：纪年视图中的某位皇帝
- `#tree-<人物 id>`：世系视图中的某个节点

**已定**：平铺模式下 hash 不再需要切换视图，只负责定位到对应 panel 的目标节点。

## 七、已定决策与理由

1. **两套视图都静态输出、平铺展示。** 世系树与纪年列表本来就是完整内容，不依赖脚本生成；平铺比 tab 切换更直观，用户可以一眼看到整体结构和时间线。
2. **HTML 树是唯一数据源。** ECharts 只做视图增强，避免 DOM 与数据两份结构漂移。
3. **帝序与血缘分开编号。** 帝序表示即位顺序，血缘连线表示亲属关系；把二者混成一条线会让人误读"父子必然相继"。
4. **过渡人物入树但不入序。** 孺子婴这类"未正式即位"的人物需要出现在世系里解释权力交接，但不应被当作第 N 位皇帝。
5. **深链记录人物。** 皇帝页最常见的分享需求是"看某一位"，只记录视图不够。
6. **全屏与导出都是显式操作。** 不自动进入全屏；导出只导出完整树，不导出当前缩放视口，避免分享时缺节点。
7. **主题切换后重建图表。** ECharts 的 canvas 不会自动跟随 CSS 变量，必须重新取色并 `setOption`。
8. **去掉"任内大事"统计。** `eventCount` 字段统计对象模糊（任内大事 vs 帝国大事界限不清），页头只保留有明确统计对象的数据项。
9. **两个 panel 平铺而非 tab 切换。** 历史帝系页的两个视图相辅相成，用户经常需要对照查看，平铺减少认知负担；同时消除了 ECharts 初始化时机依赖切换动作的问题。
10. **ECharts tooltip 丰富化。** 把原来 HTML 树里分散的 note、summary、events 汇总到 tooltip 中，hover 时一目了然；同时保留"查看纪年详情"入口让用户深入。
11. **单行扁框减少占用空间。** 皇帝节点从 3 行砍到 1 行（帝序圆+谥号+真名），symbolSize 从 192×76 缩到 156×38；在位年段和详细描述留给 tooltip。

## 八、复用边界与待定

- **过渡标签写死"西汉"（复用边界）**：`reign-timeline.html` 中过渡人物的 kicker 固定为朝代名（从 `reignView.dynasty.name` 读取）。
- **只支持单父节点（复用边界）**：`world.js` 明确拒绝一个树内节点有多个父节点。需要表达过继、双父系时，要先设计数据模型，不能绕过校验。
- **帝序口径按朝代各自定义（边界）**：西汉采用"14 位正式皇帝 + 孺子婴过渡"，东汉采用"14 位正式皇帝"。新增朝代要在 `meta.note` 写清口径，不要套用别朝规则。
- **图表初始缩放按叶子数与层数估算（待定）**：超大树可能需要手工调整 `calculateInitialZoom` 或增加缩略图导航。
- **导出文件名取页面标题（边界）**：`dynastyTitle` 来自页面 `h1`；若标题特别长，文件名也会很长。
- **移动端图表可操作性（待定）**：拖动、滚轮与按钮在触屏上的手感尚未单独验证；必要时增加手势说明或隐藏部分按钮。

## 九、家族世系变体（孙氏家谱）

家族页不再复用 `dynasty-reigns.js` 的 kinship 面板，已改为构建期生成的谱牒长卷（`family-tree-scroll.html`）；`dynasty-reigns.js` 只服务帝系双视图。

数据由 `views/*.json` 的 `type: "family-tree"` 提供：

- `figures`：树内全部人物；
- `roles`：未即位节点的身份文案；
- `orders`：同辈排序，解决生年无载人物无法按 `birth` 排列的问题；
- `emperorHref`：皇帝节点跳转的帝系页地址。

**已定**：家谱只画父系血缘，不画母族、婚姻与过继；皇帝节点保留帝序并跳转帝系页，宗室节点只作支系连接。孙河、孙韶、孙桓等本姓俞氏、因赐姓列籍的宗室不入图。

**已定**：同一父亲的子女按 `orders` 推出长幼序 `siblingRank`（1..N，跨父各自从 1 起）；皇冠只表示曾称帝，不改变排行；帝序留在卡片内；姓名为主标题，帝号只作副题。家族页最终采用谱牒长卷，ECharts 与静态全图已删除，原因见[家族世系模板](家族世系模板.md)。

**复用边界**：仍然只支持单父节点；新增家族页需要先在 `world.js` 注册 `type: "family-tree"`，不要直接套用 `dynasty-reigns` 的帝王统计文案。
