# 设计文档索引与共识

本目录记录页面模板与版式的设计取舍：为什么这样排、哪些做法已经定下、哪些还没定。新增页面或改造模板前，先在这里找最接近的现成方案，再决定是复用、扩展，还是新立模板。

## 一、与其它文档的分工

| 位置 | 管什么 | 何时读 |
| --- | --- | --- |
| `specs/` | 工程契约：目录、路由、Front Matter、构建、部署 | 动代码前先读，契约变更要同步更新 |
| `AGENTS.md` | 开发前导航与铁律 | 第一次进入项目时 |
| `docs/design/` | 模板层面的设计取舍、已定共识、待定事项 | 新增页面、改造模板、讨论需求时 |

`docs/design` 不重复 `specs` 的硬性规则，只解释“为什么”和“下一处页面该怎么照着做”。

## 二、状态标记

- **【已定】**：已实现并验证，后续页面照此复用；改动要先改文档、说明理由。
- **【试行】**：已实现，但只在一个页面验证过；复制到新页面前先复看边界。
- **【待定】**：有分歧或尚未实现，不要擅自当成先例固化。
- **【禁行】**：有明确的反面理由，不要重做。

各模板文档末尾的“待定”与“复用边界”，是讨论新需求时的默认议题表。

## 四、全局版式共识

以下规则跨模板生效。各模板文档只写自己的例外。

1. **HTML 先成立，JavaScript 只做增强。**
   - 能静态输出的内容不要留给浏览器现算。帝系双视图的两套面板、年龄明细表、史册索引都先输出完整 HTML。
   - 构建期能算好的坐标与分组在 `world.js` 算，浏览器只处理缩放、筛选、固定等交互状态。
   - 理由：无脚本、弱设备、搜索抓取和分享预览都应拿到完整内容。
   - 例外：多人生命线图与舆图依赖 JavaScript 绘制，属于已知边界，见各自文档。

2. **事实与视图分离。**
   - 人物、事件、地点、区域是事实，各自一个 JSON；专题视图只存 id 引用与展示配置。
   - 不在两个视图里重复抄写同一段生卒或事件描述。
   - 理由：同一人物会出现在多个专题，重复存储必然漂移。

3. **一处模板，多个页面。**
   - 新页面优先复用现有 include，只补数据与文案；不要复制一份模板再各自演化。
   - 必须扩展模板时，先确认新增字段对所有既有页面都有合理缺省。

4. **时间是第一坐标，写法必须显式。**
   - 负数年份表示公元前；公元前后的年长按“无公元 0 年”计算（`elapsedYears`）。
   - 帝系与群臣、年份刻度用 `eraLabel`，公元前写「前 X」，公元后写「公元 X」，不写裸数字。
   - 帝系双视图的在位/摄政年段目前仍用 `formatYear`，公元后是裸数字；详情页 `cnYear` 同样如此。统一写法见[数据契约与构建校验](数据契约与构建校验.md)的待定项。

5. **颜色、字体、主题只走变量与自托管。**
   - 颜色通过 CSS 变量引用；主题由 `data-theme` 驱动，禁止在组件里写死明暗两套色。
   - 字体、ECharts、世界地图 GeoJSON 全部本地自托管，页面不请求外部 CDN。
   - 舆图是明暗主题下都保持深色的内嵌图版，属于有意的例外。

6. **正文宽 1180px，密集图表用 `.bleed` 越界。**
   - `.container` 上限 1180px；正文内宽约 1100px。
   - 表格与图表可加 `.bleed`：宽 120% 正文，1280px 以下不启用，避免贴边。
   - 1920px 屏幕上，越界后两端各留约 300px 呼吸空间。

7. **索引页与详情页分工固定。**
   - 索引页只做导航与摘要，详情页才展开叙述。
   - 索引页不得带与集合同名的 tag（`history` / `geo` / `figure`），否则会把自身加入列表。

8. **交互默认不打扰。**
   - 悬停只预览，移开即消失；点击才固定，固定后可选中复制。
   - 固定状态要有明确提示，Esc 或点击空白处关闭。
   - 动画尊重 `prefers-reduced-motion`。

9. **移动端先保证可读，不强行压缩。**
   - 密集表格与时间轴在窄屏横向滚动，不把列压到无法辨认。
   - 越界排版只在宽屏启用；窄屏保留安全边距。

10. **页面节奏统一。**
    - 页头固定为：eyebrow（栏目英文）+ 水印 + 标题 + 导语 + 元信息。
    - 复合页面用 `00 · CAST`、`01 · LIFELINES` 这类编号分段。
    - 正文用 HTML 标签，不写 Markdown 源文件。

## 五、新增或改造模板的流程

1. **先找最接近的现成模板**，列出它已覆盖的页面与数据形态。
2. **判断是扩展还是新立**：
   - 只是多一个专题、多一组人物 → 补数据，不动模板。
   - 需要新的阅读顺序或新的坐标体系 → 新立模板，并在本目录写文档。
3. **写清数据契约**：新增字段放在哪一层、是否必填、缺省是什么、构建期如何校验。
4. **确认无脚本与窄屏行为**：至少说明“没有 JS 时看到什么”“760px 以下怎么排”。
5. **在本文档登记**：更新模板清单；新模板另建一篇文档，末尾写“待定”与“复用边界”。
6. **构建验证**：`npm run build` 通过；新增引用不能有悬空 id。
7. **提交时同改文档**：决策变了，文档和代码同一次提交，避免“代码是新的、说明是旧的”。
