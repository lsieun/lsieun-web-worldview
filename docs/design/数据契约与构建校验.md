# 数据契约与构建校验

适用于 `src/_data/world.js` 与 `_data/{figures,events,places,regions,views,dynasties}`。所有数据驱动模板都从这里取数；新增人物、事件、专题或朝代前，先确认本文的引用规则。

核心原则：**事实按实体存，视图只存引用。** 人物、事件、地点、区域各一个 JSON；专题视图只写 id 与展示配置。`world.js` 在构建期拼装并校验，任何悬空引用都会让构建失败，并指出文件名与字段。

## 一、实体目录

文件名即 id。例如 `figures/liubang.json` 的 id 是 `liubang`；重命名文件等于改 id，所有引用都会断，因此文件名视为稳定标识。

### 1.1 `figures/<id>.json`

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | 是 | 显示名 |
| `birth` / `death` | 视用途 | 数字；负数表示公元前；进入时间轴或帝系时必需 |
| `birthApprox` / `deathApprox` | 否 | 生卒为约数，标签自动加“约” |
| `careerStart` / `careerApprox` | 否 | 起家年份；帝系与群臣页使用，必须落在生卒区间内 |
| `pinyin` | 否 | 仅生僻字注音，格式如 `shì`、`mì dī` |
| `summary` | 否 | 一句话介绍 |
| `parents` | 否 | 世系父节点 id 数组；世系树当前只接受一个树内父节点 |
| `origin` / `activePlaces` | 否 | 地点 id，必须存在 |
| `milestones` | 否 | 事件 id 数组，供单人页生命线使用 |

### 1.2 `events/<id>.json`

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `year` | 是 | 数字；负数表示公元前 |
| `title` | 是 | 事件标题 |
| `desc` | 否 | 一句话说明 |
| `era` | 否 | 年号或时代注记 |
| `axis` | 否 | 是否作为多人时间轴左侧竖轴事件 |
| `key` | 否 | 是否标为转折性事件 |
| `figures` | 否 | 关联人物 id 数组 |
| `places` | 否 | 关联地点 id 数组 |

### 1.3 `places/<id>.json`

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | 是 | 地点名 |
| `lon` / `lat` | 是 | 数字 |
| `region` | 是 | 区域 id，必须存在 |
| `en` / `period` / `summary` | 否 | 展示用 |

### 1.4 `regions/<id>.json`

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` | 是 | 区域名 |
| `bbox` | 是 | `[west, south, east, north]` 四个数字 |

### 1.5 `hubs.json`（例外）

舆图不使用实体库，而是 `_data/hubs.json` 的 `places` / `routes`。原因与分界见[舆图模板](舆图模板.md)。不要把它并入实体库。

## 二、视图 `views/<id>.json`

视图类型由 `type` 决定：

| `type` | 去向 | 模板 | 说明 |
| --- | --- | --- | --- |
| 缺省 | `world.timelines[id]` | 多人时间轴 | 人物年龄对比专题 |
| `"dynasty-reigns"` | `world.reignViews[id]` | 帝系双视图 | 在位纪年 + 血缘世系 |
| `"family-tree"` | `world.familyViews[id]` | 家族世系（谱牒长卷） | 父系家谱，皇帝节点可跳转帝系页 |
| `"reign-crowd"` | `world.crowdViews[id]` | 帝系与群臣 | 帝系条 + 临朝轨 + 臣工泳道 |

### 2.1 多人时间轴视图

```json
{
  "title", "dynasty", "href", "summary", "topicMeta",
  "range": { "start", "end" },
  "meta": { "key", "watermark", "title", "subtitle", "tags",
            "intro", "lifelineHint", "tableIntro", "note" },
  "groups": [{ "id", "name", "desc" }],
  "cast": [{ "figure": "id", "group": "id", "role": "" }],
  "events": ["event-id"],
  "personalEvents": ["event-id"],
  "defaults": ["figure-id"]
}
```

- `defaults` 必须都在 `cast` 里。
- 输出时 `events` 带 `axis`、`key`、`era`，`focus` 自动取该事件的 `figures` 与 cast 的交集。
- `personalEvents` 会按人物展开成 `{year, person, title, desc}`。
- `start` / `end` 缺省时取人物生卒的最小/最大值。

### 2.2 帝系双视图视图

```json
{
  "type": "dynasty-reigns",
  "dynasty": "dynasty-id",
  "title", "href", "topicMeta", "summary",
  "figures": ["树内人物 id"],
  "meta": { "watermark", "subtitle", "tags", "intro", "note" }
}
```

- `figures` 是世系树要显示的全部节点；不在其中的父节点会被忽略。
- 帝序、在位年段、任内事件、临朝/辅政都在 `dynasties/<id>.json` 里，不写进视图。

### 2.4 家族世系视图

```json
{
  "type": "family-tree",
  "dynasty": "dynasty-id",
  "title", "href", "topicMeta", "summary",
  "emperorHref": "/history/xxx.html",
  "figures": ["树内人物 id"],
  "roles": { "figure-id": "宗室身份" },
  "orders": { "figure-id": 10 },
  "meta": { "watermark", "subtitle", "tags", "intro", "note" }
}
```

- `figures` 是家谱要显示的全部节点，仍然只走父系单父节点。
- `roles` 给未即位节点提供身份文案；皇帝节点改用 `dynasties` 里的帝号与在位年段。
- 输出节点的 `title` 固定为人物姓名，`detail` 才是帝号/身份文案；族谱不以“吴大帝”作主标题。
- `orders` 控制同辈排序（数字越小越靠前），用于生年无载、无法按 `birth` 排序的人物。
- `emperorHref` 是皇帝节点的跳转目标，点击后带上 `#timeline-<人物 id>`。

构建期由 `world.js` 追加、**不要手写**：

- `siblingRank`：同父子女按排序结果编号 `1..N`，始祖为 `null`；
- `imperialLabel`：`第 X 位皇帝` 或 `过渡人物`；
- `scrollMap`：谱牒长卷的世代列、画布尺寸与连线路径，节点另有 `scrollX` / `scrollY`；
- `branch`：支系 id（`sunqiang` / `sunjian` / `sunjing` / `root`），供长卷分色。

设计取舍见[家族世系模板](家族世系模板.md)。

### 2.3 帝系与群臣视图

```json
{
  "type": "reign-crowd",
  "dynasty": "dynasty-id",
  "title", "href", "topicMeta", "summary",
  "range": { "start", "end" },
  "meta": { "watermark", "subtitle", "tags", "intro",
            "startNote", "endNote", "note" },
  "groups": [{ "id", "name", "desc" }],
  "cast": [{ "figure": "id", "group": "id", "role": "" }],
  "events": ["event-id"]
}
```

- `range` 控制前后延伸段；`startNote` / `endNote` 写在图顶/图底的说明里。
- 所有 cast 人物必须有生卒年，且卒年不能超出视图范围。
- 事件只收本视图点名的；事件必须关联本视图人物或本朝临朝人物。

## 三、朝代 `dynasties/<id>.json`

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `name` / `start` / `end` / `order` | 是 | 朝代名、起止、排序 |
| `summary` | 否 | 史册索引组头摘要 |
| `topics` | 否 | 手挂专题：`[{title, href}]`，用于非视图类专题 |
| `rulers` | 帝系页必需 | 见下 |
| `regencies` | 否 | 临朝/辅政：`figure`, `start`, `end`, `label`, `note`, `fate` |

`rulers` 每项：

```json
{
  "figure": "id",
  "title": "汉文帝",
  "status": "formal | interim",
  "order": 1,
  "note": "",
  "terms": [
    { "start": -180, "end": -157, "durationLabel": "", "events": ["event-id"] }
  ]
}
```

规则：

- `figure` 必须在 `figures/` 存在。
- 同一 `figure` 不能在 `rulers` 里出现两次；多段在位写进 `terms`。
- `formal` 必须有整数 `order` 且全朝唯一；`interim` 不得有 `order`。
- `terms` 至少一段，`start <= end`。
- 每个事件只能分配给一个在位年段，且年份必须落在该段内。
- `regencies` 的 `figure` 必须存在，`start <= end`。

**朝代与专题的自动合并**：`world.js` 会把带 `dynasty` 的视图追加到该朝的 `topics`，标题取视图标题，`meta` 取 `topicMeta`，摘要取 `summary`。`dynasties/*.json` 里的手挂 `topics` 不会被覆盖，两者按原顺序拼接。

## 四、构建期校验清单

`world.js` 在构建时逐项检查，出错则构建失败：

**通用**

- 每个 JSON 必须能解析，且带 `name`。
- `birth` / `death` / `year` / `lon` / `lat` / `start` / `end` 必须是有限数字。
- `birth > death`、`start > end`、`start > end`（摄政）都会报错。
- 所有 `region` / `parents` / `origin` / `activePlaces` / `milestones` / `figures` / `places` / `dynasty` / `cast` / `events` / `personalEvents` / `defaults` 引用必须存在。
- `parents` 不能引用自身。

**帝系双视图**

- 正式皇帝帝序必须是正整数且不重复。
- 过渡人物不得有帝序。
- 事件不得分配给多个在位年段。
- 世系树只允许一个树内父节点；世系关系不能成环。
- 树内人物必须在 `views.figures` 与 `figures/` 中都存在。

**帝系与群臣**

- `cast` 不能重复；`group` 必须存在。
- `death` 不能超出视图 `end`。
- `careerStart` 必须落在生卒区间内。
- 事件年份必须在视图范围内，且落在所关联人物的生卒区间内。
- 事件必须关联到本视图人物或本朝临朝人物。

**多人时间轴**

- `groups` id/name 必须存在且不重复。
- `cast` 必须引用有效人物，人物必须有 `birth` / `death`。
- `cast.group` 必须存在。
- `defaults` 必须都在 `cast` 里。

## 五、反向索引

`world.js` 额外生成：

- `figure.events`：所有点名该人物的事件，按年份排序。
- `figure.milestones`：`milestones` 展开为 `{id, year, title}`。
- `place.events`：所有点名该地点的事件。
- `place.figures`：由相关事件反推的人物去重集合。

模板只读这些结果，不自己扫全库。

## 六、年份口径

- **负数 = 公元前**；数据里不写“前”字。
- **没有公元 0 年**：公元前 1 年之后直接是公元 1 年；年长、年龄、总跨度用 `elapsedYears`，不能直接 `end - start`。
- 两套格式化函数并存：
  - `formatYear`：`前 N` / `N`（公元后是裸数字）；
  - `eraLabel`：`前 N` / `公元 N`。
- 当前使用范围：
  - 帝系与群臣（`crowdView`）的事件、年段与刻度用 `eraLabel`；
  - 帝系双视图的在位年段与摄政年段用 `formatYear`；
  - `world.timelines` 的人物生卒标签用 `formatYear`；`qingTimeline.json` 直接输出数字；
  - 详情页 `cnYear` 对公元后也输出裸数字。

## 七、复用边界：西汉字样写死的位置

以下内容目前只适用于西汉专题。新增其他朝代的同类页面前，必须先把这些地方改成数据驱动：

| 位置 | 现状 | 影响 |
| --- | --- | --- |
| `world.js` `POSTHUMOUS` | 只收西汉用到的谥字与释义 | 其他朝代缺省会退化为“称号”段 |
| `world.js` `bandTitle` | 只剥离前缀“西汉” | 其他朝代称号会带全称 |
| `world.js` `dynastyYearLabel` | 固定写「汉兴第 N 年」 | 其他朝代纪年会写错 |
| `world.js` `gutterHead` / `gutterTail` | 固定写「秦末」「新莽」 | 其他朝代的前后段标注会错 |
| `reign-timeline.html` | 过渡人物固定写「西汉 · 政权过渡」 | 其他朝代出现过渡人物时会写错朝代 |

这些是**已知限制**，不是可以绕过的兼容逻辑。改数据前先改代码，或明确只做西汉专题。

## 八、新增内容步骤

新增人物：

1. 建 `figures/<id>.json`，至少写 `name`；进时间轴再加 `birth` / `death`。
2. 若人物有世系关系，补 `parents`，并确保父节点在同一视图的 `figures` 列表中。

新增事件：

1. 建 `events/<id>.json`，写 `year`、`title`，按需补 `desc`、`era`、`axis`、`key`、`figures`、`places`。
2. 在视图的 `events` / `personalEvents` 中登记；帝系页还要放进对应 `terms.events`。

新增专题：

1. 建 `views/<id>.json`，选对 `type`，指定 `dynasty`、`groups`、`cast` 或 `figures`。
2. 建对应的 `content/` 页面，按模板注入 `world.timelines[id]` / `world.reignViews[id]` / `world.crowdViews[id]`。
3. 视图会自动进入该朝 `topics`；页面 `href` 必须与真实路由一致。

新增朝代：

1. 建 `dynasties/<id>.json`，写 `name`、`start`、`end`、`order`、`summary`。
2. 史册索引会自动出现该朝分组；没有专题时显示“专题待补”。

构建报错时按提示改数据，不要绕过校验；`world.js` 的错误信息会给出文件名与字段名。

## 九、待定：公元后年份的写法

项目中同时存在两套年份格式：

| 函数 / 位置 | 公元前 | 公元后 | 当前使用 |
| --- | --- | --- | --- |
| `eraLabel` | `前 N` | `公元 N` | 帝系与群臣、年份刻度、图底标注 |
| `formatYear` | `前 N` | `N`（裸数字） | 帝系双视图的在位/摄政年段、多人时间轴人物标签 |
| `cnYear` 过滤器 | `前 N` | `N`（裸数字） | 详情页页头、人物索引卡片 |

东汉页的在位年段会显示 `25 — 220` 这类裸数字。当前读者能从上下文判断，但不符合“公元前后的年份一律显式”的目标。

**待定**：是否统一改为「公元 N」。若要改，需要同时调整 `formatYear`、`cnYear` 的调用方，并检查所有既有的帝系页与人物页标签；在决定之前，不要只改一处造成三种写法并存。
