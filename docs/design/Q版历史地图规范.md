# Q 版历史地图 · 设计规范

> 制定日期：2026-11-14 · 版本：v0.1（初版，基于孔子游历列国实践）

## 一、技术选型

| 方案 | 结论 | 理由 |
|------|:----:|------|
| **纯 SVG** | ✅ **选这个** | 零依赖、代码即数据、文本可搜索可编辑、天然支持 CSS 变量主题切换 |
| ECharts geo | ❌ | 需要 GeoJSON、坐标精确但风格受限、加载重 |
| Leaflet | ❌ | 太重（瓦片 + 坐标系统）、适合专业 GIS 不适合 Q 版 |

**核心理念**：牺牲地理精确性，换取**记忆点、可编辑性、可复用性**。历史故事地图的目的是让人记住"谁从哪到哪"，不是"这个点的精确经纬度"。

## 二、分层架构

数据文件按**从底到顶**分为 4 层，每层独立可替换：

```
┌─────────────────────────────────────────────┐
│  Layer 3  专题（journey / battle / event）   │  ← 每个历史专题一份
│  ┌─────────────────────────────────────────┐ │
│  │  Layer 2  时期（春秋 / 战国 / 三国）     │ │  ← 每个历史时期一份
│  │  ┌─────────────────────────────────────┐ │ │
│  │  │  Layer 1  通用地标（黄河/长江/山脉）│ │ │  ← 所有专题复用
│  │  │  ┌─────────────────────────────────┐ │ │ │
│  │  │  │  Layer 0  基础底图（中国轮廓）   │ │ │ │  ← 唯一的、不变的
│  │  │  └─────────────────────────────────┘ │ │ │
│  │  └─────────────────────────────────────┘ │ │
│  └─────────────────────────────────────────┘ │
└─────────────────────────────────────────────┘
```

### Layer 0 — 基础底图（唯一）

**文件**：`src/_data/qmap/base.json`

```json
{
  "viewBox": "0 0 800 600",
  "outline": "M 120,180 Q 180,100 300,90 Q 420,80 ... Z"
}
```

**职责**：
- 定义 `viewBox` 坐标系统（800×600 是固定的，所有层共用）
- 画中国大致轮廓（贝塞尔曲线，**不追求精确，追求一眼能认出是中国**）
- **不存经纬度**：Q 版是手绘坐标系，不做地理投影，SVG 坐标和真实经纬度之间没有数学映射关系。添加新点时参考锚点位置（写在注释里），用相对位置判断即可。

### Layer 1 — 通用地标（可共享）

**文件**：`src/_data/qmap/features.json`

```json

      "id": "yellow",
      "name": "黄河",
      "path": "M 130,240 Q 200,200 280,220 ...",
      "stroke": "#d4982a",
      "width": 10,
      "labelAt": [300, 228],
      "labelText": "黄 河"
    },
    {
      "id": "yangtze",
      "name": "长江",
      "path": "M 130,400 Q 220,370 320,390 ...",
      "stroke": "#4e6d8a",
      "width": 8,
      "labelAt": [320, 385],
      "labelText": "长 江"
    }
  ],
  "mountains": [
    { "id": "taihang", "name": "太行", "text": "太行", "x": 395, "y": 135, "rotate": -75 },
    { "id": "tai",     "name": "泰山", "text": "泰",   "x": 565, "y": 210 },
    { "id": "qinling", "name": "秦岭", "text": "秦岭", "x": 290, "y": 350, "rotate": -10 },
    { "id": "daxinganling", "name": "大兴安岭", "text": "大兴安岭", "x": 500, "y": 85, "rotate": -40 }
  ]

```

**职责**：
- 画**所有**专题都需要的地物：黄河、长江、泰山、秦岭、太行…
- 每个地物有 SVG path/坐标，可以被多个 period 引用
- 路径坐标和 Layer 0 的 viewBox 对齐

### Layer 2 — 时期（可选覆盖）

**文件**：`src/_data/qmap/periods/spring-autumn.json`

```json
{
  "period": "春秋",
  "periodRange": "前 770 — 前 476",
  "regions": [
    {
      "id": "lu",
      "name": "鲁",
      "shape": "poly",
      "points": "470,165 540,140 570,180 540,220 470,220",
      "fill": "#d4764a",
      "opacity": 0.35,
      "labelOffset": [510, 195]
    }
  ],
  "capitalMarkers": [
    { "id": "qufu", "name": "曲阜", "svg": [520, 200] }
  ],
  "notes": [
    { "text": "前 551 · 孔子生于鲁", "at": [520, 215] }
  ]
}
```

**职责**：
- 定义某一历史时期的政权/诸侯国色块
- 每个区块是简化的 polygon 或 rect，标注 `labelOffset` 作为国名位置
- 可选的时期特有地标（如战国的长城、三国的赤壁）

**时期文件清单**：
- `spring-autumn.json` — 春秋
- `warring-states.json` — 战国
- `qin-han.json` — 秦汉
- `three-kingdoms.json` — 三国
- `sui-tang.json` — 隋唐
- `song-yuan.json` — 宋元
- `ming-qing.json` — 明清

### Layer 3 — 专题（动态叠加）

**文件**：就是专题自己的 `{专题名}.json`（已有的 confuciusJourney.json 就是这一层）

```json
{
  "journey": [
    { "id": "qufu", "name": "曲阜", "svg": [520, 200], "year": -497, ... }
  ],
  "links": [
    { "from": "qufu", "to": "diqiu" }
  ]
}
```

**职责**：
- 专题特有的数据：路线、事件、停留点、故事
- SVG 坐标 **直接复用** Layer 2 里时期文件的坐标（同一个都城不应该有两个位置）
- 如果专题需要一个 Layer 2 没有的点，可以加 `svg` 坐标，但要确保相对位置正确

## 三、坐标约定

### viewBox：800 × 600（固定）

```
          800
  ┌─────────────────────────────┐
  │  (100,50)              (700,50)  │
  │       哈尔滨            朝鲜半岛   │
  │                                 │
600│  (100,200)          (700,200)  │
  │   乌鲁木齐   西安   上海        │
  │                                 │
  │  (100,400)          (700,400)  │
  │   拉萨      成都   广州        │
  │                                 │
  └─────────────────────────────┘
```

**锚点映射表（必须维护在 base.json 里）**：

| 城市 | SVG 坐标 | 真实经纬度 | 说明 |
|------|----------|-----------|------|
| 北京 | [430, 105] | 116.4, 39.9 | 华北锚点 |
| 西安 | [230, 215] | 108.9, 34.3 | 中原西锚 |
| 上海 | [640, 280] | 121.5, 31.2 | 华东锚 |
| 广州 | [510, 470] | 113.3, 23.1 | 华南锚 |
| 成都 | [210, 355] | 104.0, 30.7 | 西南锚 |
| 哈尔滨 | [560, 50] | 126.6, 45.8 | 东北锚 |
| 乌鲁木齐 | [100, 150] | 87.6, 43.8 | 西北锚 |
| 拉萨 | [155, 410] | 91.1, 29.7 | 西藏锚 |

### 坐标校验规则

**在添加任何新点之前，先看锚点表**。例如你要加"新郑"：

1. 新郑真实位置：113.77°E, 34.39°N
2. 对比锚点：和西安（108.9°E, 34.3°N）同纬度偏东一点，和上海（121.5°E, 31.2°N）比经度偏西、纬度偏北
3. 推理 SVG 坐标：y 应该和西安差不多（~215），x 应该在西安（230）和上海（640）之间偏西 → 大概 425
4. 验证：`{ "id": "xinzheng", "svg": [425, 215] }` — 对得上

**记住**：SVG y 值和纬度成反比（纬度越大越靠上，y 值越小）；SVG x 值和经度成正比（经度越大越靠右，x 值越大）。

## 四、渲染器规范

### 文件位置

- 通用渲染器：`src/assets/js/qmap-core.js`（从 confucius-svg.js 重构而来）
- 专题叠加脚本：每个专题一个，如 `confucius-journey.js`

### qmap-core.js API

```js
// 初始化底图（Layer 0 + Layer 1 + 可选 Layer 2）
const qmap = QMap.mount(container, {
  period: 'spring-autumn',    // → 加载 periods/spring-autumn.json
  showLabels: true,           // 显示山名、国名
  showRivers: true            // 显示黄河长江
});

// 专题层叠加（Layer 3）
qmap.overlay({
  cities: journeyPoints,      // [{ id, name, svg, ... }]
  tracks: { doneIds, activeId, allIds, links }
});

// 联动
qmap.goTo(cityId, { scale: 2, duration: 600 });   // 飞行动画
qmap.on('city-click', (e) => { ... });              // 监听标记点击
qmap.on('track-change', (e) => { ... });            // 轨迹进度变化
```

### 渲染顺序（z-index 从底到顶）

```
  Layer 3 (专题轨迹 + 标记)     ← 最前，可点击
  Layer 2 (时期色块 + 国名)
  Layer 1 (河流 + 山脉)
  Layer 0 (中国轮廓 + 纸张底色) ← 最底
```

## 五、色彩规范（用 CSS 变量）

所有颜色从 `variables.css` 读，不在 SVG 里硬编码：

| 元素 | 变量 | 默认值 |
|------|------|--------|
| 中原底色 | `--qmap-land` | `#d9cba0` |
| 中原描边 | `--qmap-land-stroke` | `#7a6c4a` |
| 黄河 | `--qmap-river-yellow` | `#d4982a` |
| 长江 | `--qmap-river-yangtze` | `#4e6d8a` |
| 诸侯国色块 | 每个 period 维护自己的 palette | 半透明（opacity 0.30-0.35） |
| 轨迹已行经 | `--color-seal` | `#bf4d28` |
| 轨迹待行经 | `--color-muted` | `#999` |
| 标记点（已完成） | `--color-seal` | `#bf4d28` |
| 标记点（未到达） | `--qmap-point-pending` | `#7a6c4a` |

### 诸侯国推荐配色（Q 版，尽量区分）

| 国 | 色 | 国 | 色 | 国 | 色 |
|----|----|----|----|----|----|
| 齐 | 金黄 #e8c94d | 鲁 | 橙红 #d4764a | 卫 | 草绿 #7b8f5c |
| 宋 | 赭黄 #d4a04a | 郑 | 青蓝 #5da3d4 | 楚 | 朱红 #b8372b |
| 晋 | 深褐 #6b5c44 | 秦 | 钢灰 #4a6670 | 吴 | 松绿 #4a9966 |
| 越 | 土黄 #7b6b3a | 曹 | 紫灰 #b08ac1 | 陈 | 玫红 #c96587 |
| 蔡 | 褐黄 #c28f3a | | | | |

**配色原则**：
- 强国（楚/齐/秦/晋）用饱和色，小国用灰调/淡色
- 相邻国家颜色要有足够对比度（鲁橙和卫绿相邻 → OK，不会混）
- 同一个国家在所有时期文件里**颜色固定**（鲁永远是橙红）

## 八、与 ECharts 地理图的关系

Q 版 SVG 和 ECharts 地理图（china-map.js）是**平行选项**，在专题页通过模式切换按钮选择。两者共享：
- 专题数据（journey / battle / event 的语义结构不变）
- 时间轴 / 详情面板 / 键盘导航等交互逻辑
- CSS 主题变量（明暗自适应）

两者差异：
| 维度 | Q 版 SVG | ECharts 地理图 |
|------|---------|---------------|
| 坐标系统 | viewBox 像素 | 真实经纬度 |
| 底图 | 手绘轮廓 | 现代省界 GeoJSON |
| 适合场景 | 故事性专题、早期历史 | 需要精确位置对比的专题 |
| 加载 | 零依赖（SVG 原生支持） | 需要 echarts.min.js + GeoJSON |
