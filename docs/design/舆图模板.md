# 舆图模板

适用于 `src/_includes/atlas.html`、`src/assets/js/atlas.js`、`src/assets/css/atlas.css`，以及 `_data/hubs.json`、`assets/data/world.json`。当前使用：首页 `/`、舆图索引 `/geo/`。

用途：一张全球底图 + 一组文明坐标 + 三条历史通道，点击坐标联动右侧档案面板。

## 一、页面结构

`atlas.html` 是一个完整 section，可直接被首页与 `/geo/` 复用：

1. **区块标题**：eyebrow、标题、导语，允许调用方覆盖：
   - `atlasEyebrow`、`atlasTitle`、`atlasIntro`。
   - 不传时用默认文案。
2. **图版 `atlas-plate`**：ECharts 世界地图 + 图例（陆上丝路 / 海上丝路 / 地中海航线 / 拖动缩放提示）。
3. **地点档案 `atlas-panel`**：服务端先渲染第一处地点，保证首屏有内容；之后由 JavaScript 更新。
4. **地点按钮条**：每处地点一个按钮，首个默认高亮。
5. **自托管说明**：写明底图为本地资源，无外部请求。

**已定**：区块自带标题，不依赖外层再套一层 section-head；首页与 `/geo/` 只通过变量改文案，不改结构。

## 二、数据契约

### 2.1 `_data/hubs.json`

```json
{
  "places": [
    {
      "id", "name", "en", "lon", "lat",
      "era", "region", "weight",
      "summary",
      "figures": ["人名"],
      "events": ["文本"]
    }
  ],
  "routes": [
    {
      "id": "land | sea | med",
      "name": "陆上丝路 / 海上丝路 / 地中海航线",
      "points": [[lon, lat], ...]
    }
  ]
}
```

- 当前为 13 处地点、3 条通道。`weight` 控制光点层级/大小。
- 图例与路线颜色按 `id` 对应三套固定颜色。
- `figures` 与 `events` 是给档案面板展示的短文本，不要求是实体库 id。
- 面板字段：中文名、英文名、年代、地域、经纬度、摘要、相关人物、历史节点。

### 2.2 `src/assets/data/world.json`

ECharts 使用的世界 GeoJSON 底图，本地自托管。`atlas.js` 通过 `fetch('/assets/data/world.json')` 加载，失败时在图版内显示“舆图数据加载失败，请刷新重试”。

### 2.3 与实体库 `_data/places` 的关系

两者**不是同一份数据**：

| 数据 | 用途 | 特点 |
| --- | --- | --- |
| `_data/hubs.json` | 舆图展示 | 面向阅读：短文本、路线、光点权重、13 处精选坐标 |
| `_data/places/*.json` | 人物与事件关联 | 面向校验：经纬度、所属区域，供 `figures` / `events` 引用 |

同一地点可能在两处都出现，修改时需保持一致；但不要把舆图文案塞进实体文件，也不要把实体引用塞进 `hubs.json`。

## 三、交互

- **点击光点**：`seriesId === 'places'` 且带 `id` 时切换档案。
- **点击地点按钮**：切到对应档案，并同步光点高亮与按钮 `aria-pressed`。
- **地图操作**：`roam: true`，可拖动平移、滚轮缩放。
- **缩放回弹**：窗口尺寸变化后延迟 160ms 调 `chart.resize()`，避免连续重排。
- **首次进入**：优先用已选地点，否则选第一处；面板不是空白等待。

**已定**：档案面板固定在右侧（窄屏落到图版下方），不弹窗、不遮图。读者看图与读档案应能同时进行。

## 四、视觉与主题

- 舆图是一块**始终深色**的内嵌图版：墨绿底、铜色光点、三色航线。
- 明暗主题切换时，舆图区不换色；这是有意的“图版”效果，不是遗漏。
- 颜色定义在 `variables.css` 的 `--atlas-*` 变量里；`atlas.js` 内另有一份同名色值（ECharts canvas 不能直接读 CSS 变量），修改主题色时两处要同步。
- 地图字体在 canvas 内使用 `JetBrains Mono` 与宋体栈，与站内一致。

## 五、已定决策与理由

1. **固定 13 处精选坐标，不做全量地点库。** 舆图回答“文明如何接驳”，不是地理百科；坐标太多会让人失去阅读焦点。
2. **路线用数据驱动，不画装饰线。** 三条通道的折点就是历史路线，改动必须改数据，不能只调样式。
3. **服务端先渲染第一处档案。** 无脚本时至少能看到一处完整档案，而不是空白面板。
4. **底图自托管。** 不依赖外部瓦片或 CDN，离线与内网都能打开，也避免第三方可用性影响页面。
5. **深色图版不跟随主题。** 地图需要稳定的明暗对比；跟随浅色主题会让光点与航线失去层次。

## 六、复用边界与待定

- **依赖 JavaScript 绘制地图（边界）**：无脚本时图版停在“正在展开舆图…”，地点按钮不可用；服务端只保证第一处档案可见。
- **新增第 14 处地点要同步文案（边界）**：首页文案写死“十三座坐标，三条通道”，`/geo/` 页头统计是动态的。新增地点时先改文案，再改数据。
- **档案面板没有详情页链接（待定）**：当前只在面板内读短档案，不能跳到 `/geo/` 的地形档案详情。是否为每处坐标建详情页，尚未决定。
- **路线折点手工维护（待定）**：`routes.points` 是一串经纬度，新增地点或改路线需手工补点，没有路径规划工具。
- **颜色双写（待定）**：`--atlas-*` 与 `atlas.js` 的 `COLORS` 需要人工同步；若后续主题色调整频繁，考虑在构建期注入或从计算样式读取。
- **移动端操作说明（待定）**：图例只写“拖动平移 · 滚轮缩放”，触屏上是否需要改成手势文案，尚未验证。
