# 详情页与索引页模板

适用于 `src/_layouts/default.html`、`src/_layouts/entry.html` 以及 `content/{history,geo,figures}/index.html`。新增普通详情页或栏目索引时，先按本文选布局，再照对应骨架填内容。

## 一、两种布局的分工

| 布局 | 用途 | 结构 |
| --- | --- | --- |
| `default.html` | 索引页、专题页、参考页 | 页头 + 内容 + 页脚，正文由页面自己组织 section |
| `entry.html` | 史册 / 舆图 / 人物详情页 | 自动生成详情页头、生命线、正文双栏、档案侧栏、返回导航 |

**已定**：详情页一律用 `entry.html`，索引与专题页用 `default.html`。不要在 `default.html` 上手搭详情页头，也不要把索引塞进 `entry.html`。

## 二、详情页结构

自上而下五段：

1. **页头 `entry-hero`**
   - 水印字由 `category` 决定：史册「史」、舆图「地」、人物「人」。
   - eyebrow 为 `{{ category }} · {{ era }}`。
   - 标题、导语（`lead`）、元信息 chips：`span`（年代，accent 色）、`region`、`coords`、`keywords`。
2. **生命线 `life-strip`**（可选）
   - 仅在同时具备 `birth`、`death`、`milestones` 时输出。
   - 轨道上的点用 `pct(year, birth, death)` 定位，悬停显示年份与标签；下方列出全部里程碑。
   - 只放“本人经历”，不放大时代背景；背景事件写在正文。
3. **正文 `prose`**
   - 用原生 HTML：`<h2>` 分节、`<p>`、`<ul>/<li>`、`<strong>`、`<blockquote>`。
   - 特殊块用 `.callout` + `.callout-label`（如 `STRUCTURE · 结构性解释`、`JUDGEMENT · 一句评价`）。
   - 首段首字下沉、`h2` 上方细线是全局正文样式，不需要页面手写。
4. **档案侧栏 `entry-aside`**
   - 固定标题 `ARCHIVE FILE`，列出类目、年代、地域、坐标、编号。
   - 编号格式 `WV · {{ page.fileSlug | upper }}`，作为页面在档案体系里的稳定标识。
   - 宽屏 sticky 在页头下方；980px 以下回落为普通块。
5. **页尾 `entry-foot`**
   - 返回对应栏目索引 + 回到首页；侧栏另有同一返回链接。

### Front Matter 契约

```yaml
---
# @formatter:off
title: "页面标题"
description: "搜索结果与分享摘要"
layout: "entry.html"
category: "史册"          # 史册 / 舆图 / 人物
tags: ["history"]         # history / geo / figure，供集合筛选
era: "秦汉"
span: "前 209 — 前 202"   # 年代或尺度
lead: "一到两句导语"
keywords: ["关键词"]
order: 1                  # 栏目内排序
# 舆图详情：en / region / coords
# 人物详情：en / region / birth / death / milestones[{year,label}]
# 史册专题：dynasty（朝代 id，用于史册索引归组）
# @formatter:on
---
```

**已定**：

- `tags` 只用于集合筛选，索引页不得带同名 tag。
- 史册专题用 `dynasty` 字段挂到朝代分组，不把条目写死在索引模板里。
- `order` 缺省按 100 处理；同一栏目内用它控制顺序。
- 负数年份直接写数字（`-209`），展示交给 `cnYear`，不要在 Front Matter 里写「前 209」。

## 三、栏目索引

三个索引页共用同一骨架，但内容组织不同。

### 3.1 共用骨架

1. `page-hero`：水印、`eyebrow`（栏目编号 + 英文）、标题、导语、`page-meta` 统计。
2. 若干 `section`：`section-head`（eyebrow / 标题 / 导语）+ 卡片网格或自定义内容。
3. 卡片用 `data-reveal` 做进入动画，由 `reveal.js` 统一处理。

**已定**：索引页只回答“有哪些内容、从哪进入”，不展开长叙述；长文一律进详情页。

### 3.2 史册索引 `/history/index.html`

- **朝代总览条**：遍历 `world.dynasties`，等宽段位横向排列，`sticky` 吸顶。
- **滚动联动**：`chronicle.js` 用 `IntersectionObserver`，页面滚到某朝代分组时高亮对应段位，并把段位滚入可见范围；点击段位平滑跳到 `#dynasty-<id>`。
- **纵向分组表**：每个朝代一行组头（名称、起止、摘要）+ 组内专题条目。
- **条目来源有两路**：
  1. `dynasty.topics`：朝代 JSON 里手挂的专题；
  2. `collections.historyEntries`：带 `dynasty` 字段的详情页，按 id 归组。
- **跨朝代专题**：如《大航海》用 `dynasty: "world"` 挂到“世界”分组，不伪造中国朝代。
- **空组占位**：`chr-empty` 仅在组内没有任何条目时显示（CSS 用相邻选择器隐藏）。
- **参考行**：标题下方单独一行指向《谥法》，参考条目不占主导航。
- **越界**：整张分组表加 `.bleed`，宽屏突破正文宽度。

**已定**：朝代顺序由 `dynasties/*.json` 的 `order` 决定，不在模板里排序；新增朝代只需加数据文件。

### 3.3 人物索引 `/figures/index.html`

- 页头统计“收录人数、时间尺度、体例”，时间尺度取自 `site.json` 的 `axis`。
- 顶部一张宽卡（`feature-card--wide`）指向清朝多人对比专题。
- 下方 `card-grid` 遍历 `collections.figureEntries`：姓名、英文名、生卒、生命线、导语、地域、跨度。
- 生命线位置用 `site.axis` 起止换算百分比。

**已定**：人物索引的尺子与详情页生命线是同一套 `site.axis`，新增人物不要另立刻度。

### 3.4 舆图索引 `/geo/index.html`

- 先放 `atlas.html`（可覆盖 eyebrow / 标题 / 导语），再放地形档案卡片网格。
- 卡片字段：坐标、标题、英文名、导语、地域。
- 更细的地图交互见[舆图模板](舆图模板.md)。

## 四、版式细则

- **水印**：页头右侧的巨大汉字，纯装饰，`aria-hidden="true"`；每类栏目固定用字。
- **eyebrow**：英文栏目名或编号，全大写；与中文标题形成“档案编号”的观感。
- **导语**：一句话说明这一页为什么值得读，不复述标题。
- **元信息**：`page-meta` / `entry-meta` 用小字号 chips，数字用 `<strong>`。
- **章节编号**：复合专题页用 `00 · CAST`、`01 · LIFELINES` 这类编号；普通详情页不编号，直接用 `h2` 分节。
- **正文节奏**：`prose` 限宽 46rem，行高约 1.98；段落之间留白，不靠缩进区分。
- **越界**：仅图表与表格使用；正文不越界。

## 五、已定决策与理由

1. **详情页与索引页两种布局，不混用。** 详情页需要档案侧栏与返回路径，索引页需要统计与卡片；混用会让两种页面都变得含糊。
2. **生命线只画个人里程碑。** 时代事件放正文或专题时间轴；若混在同一条线上，会让人误以为都是本人经历。
3. **史册条目按 `dynasty` 自动归组。** 避免每次新增专题都改索引模板；朝代分组是唯一入口。
4. **索引页统计数字尽量从数据算。** 如人物收录数取集合长度；固定文案（如史册跨度）才写死。
5. **参考条目单独一行。** 谥法属于解释工具，不是史册专题，放导航会误导层级。
6. **档案编号用文件 slug。** 改名会改变编号，因此页面文件名视为稳定标识，不随意重命名。

## 六、边界与待定

- **正向年份写法未统一（待定）**：`cnYear` 对公元后只输出裸数字（如 `195`），而帝系组件输出「公元 195」。当前详情页人物都在公元前，问题未暴露；新增跨公元后的详情页前，先决定是否统一为「公元 X」。
- **人物索引的跨度按 `death - birth` 计算（待定）**：没有扣除“无公元 0 年”的一格。当前收录人物都在公元前，暂时正确；一旦加入跨公元前后的人物，生命线长度会多一年。
- **史册跨度写死为「前 2070 — 1912」（待定）**：新增更早或更晚的朝代时需同步改页头统计。
- **索引统计里的固定数字**：首页“十三座坐标，三条通道”是文案，新增地点时要同步改文案，不能只改数据。
