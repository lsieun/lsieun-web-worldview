# 家族世系模板（孙氏家谱）

记录家族世系页的取舍：为什么按长幼排、序号与皇冠怎么分工、ECharts 全图为什么受限，以及同一份数据的交互版与静态版各自负责什么。

## 一、目标

1. **看全貌**：先回答“这一家有哪些人、分几支、谁在谁家”，而不是只看谁当了皇帝。
2. **看长幼**：同一父亲的子女按老大、老二、老三排，不因帝位、名气或生年缺载而改变位次。
3. **看帝位**：曾称帝的人在卡片顶部加皇冠，帝序写在卡片内，与长幼序分开。
4. **先成立再增强**：没有 JavaScript 也能读到完整世系；交互只负责缩放、拖动、导出。

## 二、内容规则【已定】

### 2.1 排序

- 兄弟排序由 `views/<id>.json` 的 `orders` 显式给出（数字越小越靠前），不服从此人的帝序。
- `world.js` 先按 `orders`、再按 `birth`、最后按姓名排序；没有 `orders` 时生年缺载的兄弟会排到后面，因此**新增人物必须补 `orders`**。
- 位次一旦排定，就用这套顺序生成 `siblingRank`，不另行判断谁“更重要”。

### 2.2 长幼序

- `siblingRank` 只统计**同一父亲名下的子女**：每个父亲的子女依次编号 `1..N`。
- 跨父各自从 1 开始；堂兄弟之间不连号。
- 始祖（无父节点）不编号，徽标显示「始」。
- 页面文案写「同父兄弟排行第 X」，避免读者误以为全族连续编号。

### 2.3 姓名与称谓

- 卡片主标题一律写**姓名**（`figures/<id>.json` 的 `name`），例如「孙权」「孙策」。
- 帝号、王号、官职等称谓写在主标题下方的副标题，例如「吴大帝」；族谱里不用「吴大帝」充当主名。
- 理由：族谱的检索单位是“人”，称谓会随政权、追尊与史料口径变化；先认人，再看身份。

### 2.4 皇冠与帝序

- 皇冠表示“曾称帝”，对应 `dynasties/<id>.json` 的 `rulers` 中有此人；不表示排行，也不表示正统性。
- 帝序仍保留：卡片内写「第 X 位皇帝 · 在位年段」，点击跳转帝系页。
- 一个父亲名下可以出现多个戴冠者（如孙权诸子中的孙亮、孙休），他们的长幼序互不影响。

### 2.4 本例口径

孙钟为一世；孙羌（同产兄）、孙坚、孙静按长幼并列。孙权诸子按登、虑、和、霸、奋、休、亮排；孙和一支单列孙皓。孙河、孙韶、孙桓本姓俞氏，因赐姓列籍不入图；母族、婚姻、过继不画。

## 三、ECharts 为什么看不到全图

旧版把 `scaleLimit` 固定为 `min: 1`，缩小按钮也按 `Math.max(1, ...)` 截断，所以最多只能回到初始比例，无法继续缩小。

但只放开下限还不够：

- 树布局密度由叶子数与 `symbolSize` 决定，本图 31 人、20 个叶子，横向约 `20 × 225 = 4500px`；容器只有约 1100px，整棵树的适应比例约 `0.24`。
- 旧配置 `nodeScaleRatio: 0.01` 让节点在缩放时几乎保持原尺寸；缩到 0.24 后卡片仍约 192px 宽，而节点间距只有 50px 左右，会大面积重叠。
- 把 `nodeScaleRatio` 改成 1 后卡片会一起缩小，不再重叠，但 15px 的标题在 0.24 比例下只剩约 4px，文字不可读。

因此 ECharts 能给出“结构全图”，但给不出“文字可读的全图”；这是布局密度与屏幕面积的物理限制，不是再调一个参数就能解决。

当前的处理是**按缩放级别切换详略**：缩放低于 1 时隐藏卡片标签，只留节点方块；放大回 1.08 以上再显示姓名与称谓。这样滚轮缩小不会再出现文字互相压住的情况，也不会把不可读的小字留在画布上。`全图`按钮直接进入无标签总览。

## 四、两套实现【试行】

两版共用 `world.familyViews["sun-family"]`，数据只维护一份。

| 版本 | 入口 | 做法 | 适合 | 局限 |
| --- | --- | --- | --- | --- |
| 交互版（ECharts） | `/history/sun-family.html` | 放开缩放下限到 0.12；新增「全图」按钮，按叶子数与层数算适应比例，节点随缩放等比缩小并隐藏标签；放大后恢复阅读态 | 拖动画布、逐支细读、导出 PNG | 全图时文字不可读，皇冠只能排在标题前，无法真的“压在头顶” |
| 静态版（SVG） | `/history/sun-family-map.html` | 构建期在 `world.js` 算好列/行坐标，输出整棵树的 `<svg>`；卡片、连线、长幼序、皇冠全部静态 HTML | 一眼看全貌、无脚本、可打印、可被搜索抓取 | 没有拖拽与逐节点缩放；树更大时需要页面纵向滚动 |

静态版的坐标规则：

- 列 = `generation`（从始祖向下），列宽 200px；
- 行 = 叶子节点自上而下依次占行，行高 50px；父节点纵向居中于首末子女；
- 卡片 150 × 42px，只放姓名、身份摘要、长幼序与皇冠；完整身份与在位年段仍由原交互版承载。

## 五、其它候选【待定】

| 方案 | 吸引力 | 代价 | 结论 |
| --- | --- | --- | --- |
| AntV G6 TreeGraph | `fitView` 原生支持全图，自定义节点可精确画出头顶皇冠 | 需再自托管约 500KB 依赖；节点/边配置是另一套 API | 树更大或需要折叠分支时再评估 |
| D3 自绘 SVG | 布局与节点完全可控，可按缩放级别切换详略 | 需自己实现平移缩放、标签避让与键盘操作 | 与现有静态 SVG 思路重叠，暂不引入 |
| 思维导图库（jsMind / Markmap） | 横向展开直观 | 节点定制弱，皇冠、长幼序、帝序难同时表达；默认不适合“父系单线”阅读 | 不采用 |

选型建议：**日常阅读用交互版，需要全貌与打印用静态版**；两者并存，不互相替代。

## 六、数据契约新增

`world.familyViews[id]` 在原有节点字段上新增：

| 字段 | 层级 | 说明 |
| --- | --- | --- |
| `siblingRank` | 节点 | 同父子女的 1..N 序号；始祖为 `null` |
| `imperialLabel` | 节点 | `第 X 位皇帝` / `过渡人物`；非皇帝为空串 |
| `map` | 视图 | 静态版布局：`width`、`height`、`nodeWidth`、`nodeHeight`、`edges[{from,to,path}]` |
| `mapX` / `mapY` | 节点 | 静态版卡片左上角坐标（构建期计算，不在视图 JSON 里手写） |

节点输出的 `title` 固定为姓名，`detail` 为称谓：皇帝节点取 `rulers` 的 `title`（如「吴大帝」），宗室节点取 `roles` 的身份文案。模板与 ECharts 标签都按“姓名在上、称谓在下”渲染，不要再把帝号当主标题。

视图 JSON 只新增可选展示字段：

```json
{
  "meta": { "mapHref": "/history/sun-family-map.html" }
}
```

- `mapHref` 存在时，交互版显示“静态全图版”对照入口。
- `siblingRank` 由 `orders` 排序结果推导，**不要**在 JSON 里手写；改 `orders` 即改长幼序。
- 皇冠与 `imperialLabel` 由朝代 `rulers` 推导，家谱视图不重复维护帝序。

## 七、页面与入口

| 页面 | 数据 | 模板 |
| --- | --- | --- |
| `/history/sun-family.html` | `world.familyViews["sun-family"]` | `src/_includes/family-tree-page.html` |
| `/history/sun-family-map.html` | 同一份数据 | `src/_includes/family-tree-map.html` |

史册索引只登记交互版；静态版作为对照实现由交互版页内链接进入，不重复占索引位。

## 八、复用边界与待定

- **单父节点（复用边界）**：仍只支持一个树内父节点；过继、双父系要先改数据模型。
- **长幼序只到同父（已定）**：不提供全族连续编号；需要“第几世 + 第几子”时，另加世次字段，不要把两套编号混成一个徽标。
- **皇冠口径依赖 `rulers`（边界）**：追尊、未正式即位者是否戴冠，取决于该朝 `rulers` 是否收录；家谱页不单独判定。
- **静态版密度（待定）**：当前按 31 人调固定列宽/行高；超过约 60 人时需要换分层展开或分组折叠。
- **交互版全图标签（待定）**：全图模式隐藏标签目前是硬编码；若以后要“全图也能读名字”，需要按缩放级别切换简写标签，或改用 G6。
