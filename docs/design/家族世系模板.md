# 家族世系模板（孙氏家谱 · 谱牒长卷）

记录孙氏家谱的最终实现：为什么按长幼排、姓名与帝号怎么分工、为什么放弃 ECharts 与静态全图，以及长卷的布局和交互边界。

## 一、目标

1. **看全貌**：先回答“这一家有哪些人、分几支、谁在谁家”，而不是只看谁当了皇帝。
2. **看长幼**：同一父亲的子女按老大、老二、老三排，不因帝位、名气或生年缺载而改变位次。
3. **看帝位**：曾称帝的人在卡片顶部加皇冠，帝序写在卡片内，与长幼序分开。
4. **先成立再增强**：没有 JavaScript 也能读到完整世系；交互只做悬停点亮与小传。

## 二、内容规则【已定】

### 2.1 排序

- 兄弟排序由 `views/<id>.json` 的 `orders` 显式给出（数字越小越靠前），不服从此人的帝序。
- `world.js` 先按 `orders`、再按 `birth`、最后按姓名排序；没有 `orders` 时生年缺载的兄弟会排到后面，因此**新增人物必须补 `orders`**。
- 位次一旦排定，就用这套顺序生成 `siblingRank`，不另行判断谁“更重要”。

### 2.2 长幼序

- `siblingRank` 只统计**同一父亲名下的子女**：每个父亲的子女依次编号 `1..N`。
- 跨父各自从 1 开始；堂兄弟之间不连号。
- 始祖（无父节点）不编号，朱印显示「始」。
- 页面文案写「同父兄弟排行第 X」，避免读者误以为全族连续编号。

### 2.3 姓名与称谓

- 卡片主标题一律写**姓名**（`figures/<id>.json` 的 `name`），例如「孙权」「孙策」。
- 帝号、王号、官职等称谓写在主标题下方的副标题，例如「吴大帝」；族谱里不用「吴大帝」充当主名。
- 理由：族谱的检索单位是“人”，称谓会随政权、追尊与史料口径变化；先认人，再看身份。

### 2.4 皇冠与帝序

- 皇冠表示“曾称帝”，对应 `dynasties/<id>.json` 的 `rulers` 中有此人；不表示排行，也不表示正统性。
- 帝序仍保留：卡片内写「第 X 位皇帝 · 在位年段」，点击人物小传后另有帝系页入口。
- 一个父亲名下可以出现多个戴冠者（如孙权诸子中的孙亮、孙休），他们的长幼序互不影响。

### 2.5 本例口径

孙钟为一世；孙羌（同产兄）、孙坚、孙静按长幼并列。孙权诸子按登、虑、和、霸、奋、休、亮排；孙和一支单列孙皓。孙河、孙韶、孙桓本姓俞氏，因赐姓列籍不入图；母族、婚姻、过继不画。

## 三、为什么放弃图表方案【已删除】

### 3.1 ECharts 交互版

旧版把 `scaleLimit` 固定为 `min: 1`，缩小按钮也按 `Math.max(1, ...)` 截断，最多只能回到初始比例。放开下限后仍然有两个问题：

- 树布局密度由叶子数与 `symbolSize` 决定，本图 31 人、20 个叶子，横向约 `20 × 225 = 4500px`，一屏适应比例约 `0.24`；
- 节点缩小、标签保留时，15px 的文字在 0.24 比例下只剩约 4px；节点保持原尺寸时又会大面积重叠。

ECharts 能给出“结构全图”，给不出“文字可读的全图”。它仍适合帝系页的血缘小树，但不适合承担 31 人的家族主图，因此家族页不再使用。

### 3.2 静态 SVG 全图

静态版坐标正确、无脚本可用，但只有“线 + 方框”，缺少世代层次、支系区分与材质，读起来仍像工程图。它已被长卷版吸收并删除。

### 3.3 markmap【禁行】

markmap 是思维导图：节点是文本条目，无法给单人做“姓名 + 帝号 + 朱印 + 头顶皇冠”的复合卡片；长幼只能靠缩进表达，31 人、5 世的谱系会被拉得很宽。若以后需要“家族目录/索引”，可以另做一张 markmap，但不要承担主图。

## 四、长卷实现【已定】

页面由构建期生成完整 SVG，JS 只增强交互。

### 4.1 布局

- **五世成列**：`generation` 为列，列宽 250px；一世到五世各有淡色列带与虚线世次刻度。
- **行**：叶子节点自上而下依次占行，行高 68px；父节点纵向居中于首末子女。
- **卡片**：200 × 58px，顶部起脊、下沿收平，内框细线，左上角朱印，右侧姓名与称谓。
- **连线**：父右缘到子左缘，转角用二次曲线做圆角；皇帝与普通宗室使用同一套线宽。

### 4.2 视觉

- **三支分色**：孙羌支朱红（`--color-seal`）、孙坚支铜金（`--color-brass`）、孙静支青瓷（`--color-celadon`），只染卡片左侧饰条、连线与图例。
- **朱印长幼**：同父序号写成方形朱印，白字；始祖印「始」。
- **鎏金皇冠**：皇帝卡片顶部压一枚金冠，卡内再加一圈鎏金细框；帝号仍是副题。
- **纸感与画框**：淡纸纹、双线内框、极淡铜金色晕，全部走 CSS 变量，明暗主题自动切换。

### 4.3 交互

- **悬停/聚焦**：点亮从始祖到该人的世系路径，其余节点与连线淡出。
- **点击**：打开人物小传（姓名、帝号、长幼、帝位、在位年段、帝系页入口），Esc 或 × 收起；不打断当前页面。
- **无 JS**：全部卡片、连线、序号与皇冠照常可见；皇帝卡片的 `<a>` 仍可跳转帝系页。

### 4.4 入口

`/history/sun-family.html` 由 `family-tree-scroll.html` 渲染，交互逻辑在 `assets/js/family-tree-scroll.js`。

## 五、数据契约

`world.familyViews[id]` 的节点字段：

| 字段 | 说明 |
| --- | --- |
| `siblingRank` | 同父子女的 1..N 序号；始祖为 `null` |
| `imperialLabel` | `第 X 位皇帝` / `过渡人物`；非皇帝为空串 |
| `branch` | 支系 id：`sunqiang` / `sunjian` / `sunjing` / `root` |
| `scrollX` / `scrollY` | 卡片左上角坐标（构建期计算，不手写） |

视图字段：

| 字段 | 说明 |
| --- | --- |
| `scrollMap.width` / `height` | 画布尺寸 |
| `scrollMap.nodeWidth` / `nodeHeight` | 卡片尺寸 |
| `scrollMap.generations` | `[{index, label, x, width}]`，世次列带 |
| `scrollMap.edges` | `[{from, to, branch, path}]`，已算好的圆角连线路径 |

- 节点输出的 `title` 固定为姓名，`detail` 为称谓：皇帝取 `rulers` 的 `title`，宗室取 `roles` 的身份文案。
- `siblingRank` 由 `orders` 排序结果推导，**不要**在 JSON 里手写；改 `orders` 即改长幼序。
- 皇冠与 `imperialLabel` 由朝代 `rulers` 推导，家谱视图不重复维护帝序。
- 长卷坐标全部在 `world.js` 计算，视图 JSON 不写像素值。

## 六、复用边界与待定

- **单父节点（复用边界）**：仍只支持一个树内父节点；过继、双父系要先改数据模型。
- **长幼序只到同父（已定）**：不提供全族连续编号；需要“第几世 + 第几子”时，另加世次字段，不要把两套编号混成一个徽印。
- **皇冠口径依赖 `rulers`（边界）**：追尊、未正式即位者是否戴冠，取决于该朝 `rulers` 是否收录；家谱页不单独判定。
- **密度（待定）**：当前按 31 人调列宽/行高；超过约 60 人时需要换分层展开或分组折叠。
- **移动端（待定）**：长卷在窄屏按比例缩小，人物小传改为底部卡片；触屏上的悬停效果不可用，需依赖点击。
- **打印（待定）**：纸纹与阴影在打印时可能偏重，正式导出前需单独校准。
