# 拼音与注音排版规范

记录生僻字注音在页面上的字体处理方式。适用于帝系卡片、人物卡片与《谥法》页。

## 一、问题

注音里的声调字母（`ā á ǎ à`、`ē é ě è`、`ī í ǐ ì`、`ō ó ǒ ò`、`ū ú ǔ ù`、`ǖ ǘ ǚ ǜ`）并不在基本拉丁区。

项目自托管的 Inter 只加载了 `latin` 分片，遇到 `ǎ`（U+01CE）、`ì`（U+00EC 之外的扩展字符）时缺字形，浏览器回落到系统中文字体去补。结果是同一个括号里，`sh` 用 Inter、`ì` 用宋体——字重、宽度、基线都不一致，看上去像拼错了。

这不是排版参数问题，是字体覆盖问题。调字号、字距都修不好。

## 二、解法

Inter 官方分片里本来就有 `latin-ext` 与 `vietnamese`，后者覆盖越南语全部带声调字母，与拼音所需字符高度重合。把它们注册进同一个字体族，并用 `unicode-range` 限定作用范围：

```css
@font-face {
    font-family: 'Inter Variable';
    src: url('/assets/fonts/inter/files/inter-latin-ext-wght-normal.woff2') format('woff2-variations');
    font-weight: 100 900;
    font-display: swap;
    unicode-range: U+0100-024F, U+1E00-1EFF;
}
```

要点：

- `unicode-range` 必须写，否则扩展分片会与基本拉丁分片争抢同一段码位。
- 不新增字体族，仍是 `Inter Variable`；调用处无需改字体名。
- 中文不交给 Inter，靠字体栈回落：

```css
font-family: 'Inter Variable', var(--font-serif);
```

这样拉丁字母（含声调）用 Inter，汉字仍用系统宋体，字形不变。

## 三、落点

| 位置 | 文件 | 处理 |
| --- | --- | --- |
| 卡片标题（`刘奭（shì）`） | `src/assets/css/reign-crowd.css` `.rc-tip-title` | Inter 优先，宋体回落 |
| 谥法页拼音 | `src/assets/css/components.css` `.posthumous-pinyin` | 由 JetBrains Mono 改为 Inter |
| 字体分片注册 | `src/assets/css/fonts.css` | 新增 latin-ext、vietnamese 两个 `@font-face` |

谥法页原来用等宽字体，等宽字体对声调符号的支持更不稳定，且与正文的宋体节奏不合，故一并改为 Inter。

## 四、数据规则

- 拼音写在人物数据的 `pinyin` 字段，模板不硬编码。
- 只在生僻字上注音，不必全名注音。目前：`刘奭 shì`、`刘骜 ào`、`刘衎 kǎn`、`金日磾 mì dī`。
- 展示格式统一为 `汉字（拼音）`，多音节用空格分隔，例如 `金日磾（mì dī）`。
- 声调符号使用预组合字符（`ǎ` 为单码位），不要用「字母 + 组合附加符」拆写，否则换行与选中有隐患。

## 五、不采用的方案

- **LXGW WenKai Mono**：CJK 字体，单字重数 MB，多字重十几 MB；拉丁部分为等宽，与宋体标题混排显得机械。为一个括号里的注音引入整套 CJK 字体，代价与收益不成比例。
- **浏览器端拼字**：把 `a` 与组合声调符号叠加，看似省字体，实际在不同平台的重心与间距不可控。

## 六、后续可选

若以后要求中文标题与拼音风格完全统一，正确路径是子集化：只抽取页面实际用到的汉字与拉丁扩展字符，生成一个几百 KB 的字体文件，而不是整包引入 CJK 字体。做之前应先统计全站用字，否则子集缺字会在新页面突然回落。
